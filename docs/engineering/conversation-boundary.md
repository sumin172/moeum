# 연속 입력과 응답 실행 단위

## 문제

사용자는 하나의 이야기를 여러 메시지로 나눠 보낸다. AI 답변을 읽기 전에 다음 메시지를 보내면 메시지마다 따로 답하는 방식은 대화가 엇갈려 보인다.
메시지마다 응답 작업을 두면 같은 기록 안의 선후관계, 과거 실패 답변의 재삽입 여부, 묶어서 답할 때 어느 작업이 답변을 소유하는지를 별도로 판단해야 한다.

## 판단

응답 실행 단위는 기록이다. 기록당 응답 작업 하나가 아직 답하지 않은 USER 입력을 순서대로 모아 한 번에 답한다.

| 대안               | 판단 | 근거                                                                                                      |
|--------------------|------|-----------------------------------------------------------------------------------------------------------|
| 메시지별 응답 작업 | 기각 | 메시지별 응답·재시도에는 맞지만, 묶음 응답에서 답변 소유와 완료 처리, 작업 간 선후·재삽입 판단이 추가된다 |
| 기록별 응답 작업   | 채택 | 기록 안의 실행이 원래 직렬이므로 실행 경계가 같고, 작업 간 선후관계와 재삽입 판단이 필요 없다             |

현재 규칙과 상태 전이는 [대화 계약](../CONVERSATION.md)에 있다.

| 상태                  | 저장 위치                       | 근거                                                                                    |
|-----------------------|---------------------------------|-----------------------------------------------------------------------------------------|
| 답변 완료 경계        | ASSISTANT의 원본 순번에서 계산  | 응답 저장과 작업 전이가 같은 트랜잭션이라 별도 저장 없이 일관된다                       |
| 실행 주기의 관측 상한 | 작업의 observed_source_revision | 실행 중 접수분을 접수 시점과 무관하게 판별하고, 같은 입력으로 재개가 반복되지 않게 한다 |
| 실제 답변 범위        | 저장하지 않고 실행 시 계산      | 메시지가 바뀌지 않으므로 같은 설정에서는 같은 범위가 된다                               |

실제 답변 범위를 저장하지 않으므로 보장 수준은 "관측 상한 고정, 실제 처리 범위는 현재 설정으로 계산"이다.
글자 예산이나 선택 방식이 배포로 바뀌면 재시도의 범위가 달라질 수 있다. 다음 범위는 저장된 답변 완료 경계에서 시작하므로 누락·중복은 생기지 않는다.
이 서비스에 필요한 것은 같은 요청의 재현성보다 접수된 내용을 순서대로 빠짐없이 답하고 중복 결과를 막는 것이라 이 차이를 수용했다.

최종 실패 뒤의 새 메시지는 미응답 내용을 함께 답하는 제한된 실행 기회를 다시 연다. 새 메시지를 복구 의사로 보는 합의된 경험이다.
실패 원인을 저장하지 않으므로 인증·설정 오류도 새 메시지마다 다시 호출될 수 있다. 기록당 접수 한도와 누적 시도 상한으로 횟수가 유한하고, 운영 장애는 로그·메트릭으로 감지한다.
재개 가능 시각은 FAILED의 next_attempt_at에 두어 새 메시지와 수동 재시도가 같은 공급자 대기를 지킨다.

## 예정 방향

첫 미응답 입력부터 고정된 짧은 대기를 두고 그동안 모인 입력에 답한다. 이 동작은 "입력을 멈춘 뒤 답한다"가 아니라 "첫 입력 후 일정 시간이 지나면 그때까지 모인 말에 답한다"이다.
작성 중 신호는 실행 전 대기를 조정하되 재시도 대기를 당기지 않고 최대 대기를 넘기지 않는다.
대기 시간·신호 API·시간 표현은 화면 개발과 함께 정한다. 현재 서버는 대기 없이 실행할 차례가 되면 답하며, 실행 주기를 시작하는 선점 시점까지 접수된 미응답 입력이 함께 묶인다.
같은 주기의 재시도·리스 회수는 관측 상한 이후 입력을 포함하지 않으며, 그 입력은 다음 실행 주기에서 답한다.

## 검증

ResponseJobExecutorTest는 묶음 응답, 실행 중 접수의 이어 답하기, 재시도의 관측 상한 유지, 최종 실패 뒤 재개, 예산 분할의 누락·중복 방지, 호출 수 여유 상한((2Q+1)×누적 시도 상한)을 시나리오로 검사한다. 일반적인 증명은 아니다.
ConversationOrderingIntegrationTest는 실제 PostgreSQL에서 동시 재개 1회, 잠금 뒤 관측 상한, 오래된 워커의 저장 거절, 조회 도중 완료된 답변에 대한 단일 스냅샷 응답을 검사한다.

## 재검토 조건

- 실제 사용자의 재개 호출이 인증·설정 오류로 반복돼 비용이 관측된다. 그때는 실패 원인 저장을 검토한다.
- 같은 설정에서 재시도 범위의 재현이 업무 요구가 된다.

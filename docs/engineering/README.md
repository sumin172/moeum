# 개발 사례

이 문서 묶음은 설계 선택의 문제·대안·판단·검증 근거를 설명한다.
현재 제품 정책과 서버 계약은 [개발 문서](../README.md)를 따른다.

| 사례                                                     | 핵심 질문                                                                 |
|----------------------------------------------------------|---------------------------------------------------------------------------|
| [연속 입력과 응답 실행 단위](conversation-boundary.md)   | 연속 입력을 함께 답하려면 응답 실행 상태를 어떤 단위로 둘 것인가?         |
| [DB 작업 큐와 대안 비교](job-queue.md)                   | 메시지 브로커나 작업 라이브러리 대신 DB 작업 큐를 유지할 근거는 무엇인가? |
| [LLM 공급자 용도별 분리](llm-provider-split.md)          | 무료 티어 한도 안에서 대화와 일기의 공급자를 어떻게 나눌 것인가?          |
| [실행 역할별 빈 등록](execution-role-registration.md)    | 같은 jar의 역할별 빈 구성을 어떤 방식으로 나누고 보호할 것인가?           |

사례는 설계 판단으로서 남길 가치가 있는 것만 둔다. 단순 변경 이력·삭제 목록·완료 체크리스트·일회성 실행 덤프는 남기지 않는다.
수치는 기록된 실행 조건에서의 관측값이며 원인과 상관관계를 구분한다.
재검토 조건은 해당 사례 문서 안에 둔다.

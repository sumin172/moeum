# 개발 사례와 시행착오

이 문서 묶음은 개발 과정에서 드러난 문제와 기획 선택, 검증 근거를 설명한다.
현재 제품 정책과 서버 계약은 [개발 문서](../README.md)를 따른다.

| 사례                                                          | 핵심 질문                                                             |
|---------------------------------------------------------------|-----------------------------------------------------------------------|
| [시간 경계와 생성 입력](record-boundary.md)                   | 마감 뒤의 대화와 재시도 입력을 어떤 기존 데이터로 구분할 수 있는가?   |
| [필수 상태와 중복 데이터](minimal-state.md)                   | 업무에 필요한 상태와 관행적으로 추가한 상태는 어떻게 다른가?          |
| [실패 격리와 작업 수명](job-lifecycle.md)                     | 복구 보장을 지키면서 재시도와 작업 보존 비용을 제한할 수 있는가?      |
| [DB 접근과 실행 슬롯](database-and-workers.md)                | 커넥션과 선점 비용은 어떤 실제 병목을 만들었는가?                     |
| [성능 시험의 범위와 해석](capacity-validation.md)             | 통과한 수치가 무엇을 보장하고 무엇을 보장하지 않는가?                 |
| [사용량 경계와 연속 입력](usage-and-conversation-boundary.md) | 일기 구간과 사용량 기간을 어떻게 맞추고 연속 입력에 언제 답할 것인가? |

기계적인 삭제 목록·완료 체크리스트·일회성 실행 덤프는 사례의 범위 밖이다.
수치는 기록된 실행 조건에서의 관측값이며 원인과 상관관계를 구분한다.

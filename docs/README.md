# 모음 개발 문서

2026-10-12 현재 재설계 기준과 구현 계약이다. 과거 아키텍처/단계 문서는 새 내용으로 대체했다.
현재 운영 코드가 아래 목표 구조로 모두 구현됐다는 뜻은 아니다.

## 읽는 순서

1. [아키텍처](ARCHITECTURE.md): 서비스 목표, 모듈 소유권, 트랜잭션과 실행 역할.
2. [하루 기록](RECORD_DAY.md): 마감·타임존·오프라인·사용자 수정 정책.
3. [부하 기준](CAPACITY.md): 사용자 급증과 일기 배치 격리의 검증 목표.
4. [개발 원칙](PRINCIPLES.md): 구현·삭제·스키마·검증 규칙.
5. [개발 단계](DEVELOPMENT_STAGES.md): 한국어 이슈와 영어 브랜치별 작업 범위.
6. [대화 계약](CONVERSATION.md): 서버 한도, 응답 순서, 메시지 커서와 작업 상태 조회.
7. [일기 계약](JOURNAL.md): 자동 보관, 구독 수정, 작업 소유권과 수정본 보호.
8. [실행 역할](WORKER_ROLES.md): 실행 방법, 현재 자원 예산과 검증 범위.
9. [관측·보존](OBSERVABILITY_RETENTION.md): 안전한 구조화 로그, 메트릭, 완료 작업 정리 계약.
10. [코드 정리 점검](CLEANUP_AUDIT.md): R1~R5의 잔여 코드·컬럼·의존성 점검 결과.

## 확정한 방향

- Conversation과 Journal 모듈 유지, Journal 실행 부하 격리.
- Conversation이 하루 기록·마감 예약을 소유.
- 원본 스캔 대신 작은 예약/미전달 상태로 생성 대상을 전달.
- 자동 일기 보관·조회 제공, 생성된 일기 직접 수정은 구독 기능, 사용자 수정본 보호.
- 무료·구독 모두 유한한 대화 한도. 구독은 한도를 늘리며 클라이언트에 한도·잔여 횟수를 미리 공개.
- 한도 소진 시 클라이언트와 서버 모두 새 메시지 접수를 차단. 이미 접수한 대화로 일기 생성.
- AI 재작성·문체·길이 설정은 현재 범위에서 제외.
- 생성 입력 확정 이후 도착한 새 원본은 조용히 폐기하고 기존 일기는 자동 갱신하지 않음.
- 폐기 결과는 내부 응답으로만 구분하고 클라이언트는 알림 없이 전송 대기열에서 제거.
- DB는 업무 상태, 관측 시스템은 진단 상세를 담당.
- 데드 코드 즉시 제거, 신규 DB 기준 Flyway 초기 이력 재작성.

## 명시적 가정

마감 후 대화는 다음 기록으로 모으는 기본안을 사용한다.
새벽 표시 날짜의 정오 구분, 미래 입력 5분, 기록 길이 36시간은 정책 가정이다.
실사용 전 조정할 수 있으며 사용자 확정값으로 취급하지 않는다.

P0/P1/P2 부하와 지연 목표는 검증 계획이다.
6개월 성장 예측, 공급자 한도, 운영 사양은 아직 확인되지 않았다.
운영 코드 구현·실제 공급자 스모크·성능 검증은 각각 별도 상태로 보고한다.

## 현재 구현 범위

API·대화 응답·일기 생성 실행 역할 분리와 RecordDay 기반 귀속·마감·Journal 전달·생성 입력 동결을 구현했다.
실행 방법과 검사 범위는 [실행 역할](WORKER_ROLES.md)을 따른다.
Flyway V1부터 신규 DB 초기 이력을 사용하며 V3/V4에 기록·전달·기록 ID 기반 스키마를 구성한다.
구독별 서버 한도, 기록별 응답 순서·입력 상한, 메시지 커서·작업 상태 묶음 조회를 구현했다. 계약과 개발 기본값은 [대화 계약](CONVERSATION.md)을 따른다.
생성 즉시 일기 조회, 구독자의 직접 수정과 수정본 보호를 구현했다. 일기 확정·리비전·JSON 저장 wrapper는 제거하고 본문을 TEXT로 저장한다. 상세 계약은 [일기 계약](JOURNAL.md)을 따른다.
LLM 호출 진단은 bounded 로그·메트릭으로 분리하고 역할별 완료 작업 보존·정리를 구현한다. 계약과 검증 한계는 [관측·보존](OBSERVABILITY_RETENTION.md)을 따른다. 대규모 부하·복구 검증은 R6 범위다.
기록 ID API와 마감 전달의 구현 계약은 [하루 기록](RECORD_DAY.md)을 따른다.
P0/P1/P2 부하와 실제 공급자 용량은 아직 측정하지 않았다.

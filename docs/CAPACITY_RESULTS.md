## 복구와 도구 검증

- 429·timeout·5xx 각 25건은 모두 2회 이내 시도로 완료된다.
- 일기 JVM 종료로 남은 PROCESSING 2건은 운영 5분 리스 후 회수되어 대상 일기 3건이 완료된다.
- 일기 워커가 없는 동안 대화 25건이 접수·완료된다.
- 전달 등록 직전·직후 종료는 각각 작업 1건·일기 1건으로 복구된다.
- 복구 시험의 중복 응답·일기는 0건이다.
- 일기 완료 후 수정 권한·버전 충돌·다음 기록 귀속 검사는 짧은 P0에서 일기 10건과 함께 통과한다.

이는 무료 티어 시험의 실제 청구액이 아니며, 하루 동안의 AI 대화 응답·재시도·향후 단가 변경은 포함하지 않는다.

합성 입력 구성 단위 시험은 무료 20개·구독 100개 USER가 각각 4,000자이고 마지막 USER까지만 포함됨을 검사한다.
실제 공급자 실행·결과 파일 규격은 [실행 절차](CAPACITY_RUNBOOK.md)의 journalProviderTest를 따른다.

## 실제 공급자 품질·반복 실행

2026-10-24에 gemini-3.6-flash로 대표 대화·면접 정정과 부정·계획 취소와 지갑 회수의 3개 합성 사례를 검증했다.
사례별 대화·일기 각각 정상 출력 2개를 확보했다. 전체 시도는 15회, 정상 생성 12회·HTTP 429 실패 3회이며 자동 재시도는 없다.

| 경로 | 정상 생성 | 실패         | 성공 지연 범위 |
|------|-----------|--------------|----------------|
| 일기 | 6/6       | 0            | 5,330~6,702ms  |
| 대화 | 6/9       | HTTP 429 3건 | 1,400~2,891ms  |

실패는 RESOURCE_EXHAUSTED·FREE_TIER_AVAILABILITY로 분류됐다. 면접 대화 1회와 계획 변경 대화 2회에서 발생했다.
호출 가용성과 출력 품질은 별도 판정이며 무료 티어의 연속 호출 안정성은 보장하지 않는다.
6개 일기의 수동 검토에서는 장소 정정, 칭찬에 대한 부정, 면접 결과 미확정, 취소한 등산·영화와 실제 도서관 방문·지갑 회수를 기대대로 확인했다.
생성된 대화 6개는 사용자의 마지막 발화에 반응하고 후속 질문을 제공했으며 합격·칭찬 같은 잘못된 사실을 단정하지 않았다.
표본이 작으므로 일반적인 품질·운영 가용성의 보장은 아니다.

계획 변경 대화는 지갑 회수와 도서관 방문에 반응했다. 면접 대화의 한 출력은 `어떤 하며`라는 어색한 표현을 포함했다.
또 다른 질문에는 사용자가 말하지 않은 식사를 전제하는 것으로 읽힐 수 있는 표현이 있었다. 중요한 사실의 단정적 왜곡은 확인하지 않았지만 문장 자연스러움과 질문의 전제는 개선 여지가 있다.
선정 모델은 gemini-3.6-flash이며 개발·베타의 무료 API 이용과 위 품질 제약은 수용된 상태다. 무료 티어 처리량이나 무중단 보장과는 별개다.

## 관측한 간헐 현상

25 RPS 워밍업에서 SQLTransientConnectionException이 기록돼 본 측정을 시작하지 못한 실행이 있다.

30분 검증의 전체·구간별 지연은 별도 조건의 실측값이다.

일기 워커를 901초에 중단하고 962초에 재기동을 요청했다. 982초 표본에서 준비 완료를 확인했고 1분 최초 정리 대기 후 1,042초 표본에서 적체가 새 유입 한 묶음 수준으로 회복됐다.
중단·재기동 인근 900~1,050초의 30초 구간별 응답 대기 p95는 68.7~80.1ms다. 앞선 4분 시험의 2.72초 p95는 이 실행에서 재현되지 않았다.
DB 대기 표본에는 지속적인 잠금 대기가 없었고 WAL 쓰기·autovacuum 지연 표본이 각각 한 번 있었다. 10초 표본은 그 사이의 짧은 대기를 모두 포착하지 못한다.
역할별 heap 표본 최고는 API 125.1MiB·대화 119.5MiB·일기 117.2MiB, DB 풀 대기 표본 최고는 API 1·워커 0이며 로그·telemetry 드롭은 0이다.

DB 크기는 첫·마지막 표본에서 625.9→873.6MiB다. 원본 보존과 최근 작업의 유입을 포함한 물리 크기이며 정리 작업이 DB 크기를 일정하게 유지한다는 의미가 아니다.
30일 경과는 과거 시각을 넣어 압축 재현했고 실제 30일·수개월 누적 데이터나 백업 용량을 시험하지 않았다.

따라서 이 30분 범위의 유입·정리 균형은 확인됐지만, 반복 실행 안정성과 콜드 스타트·재기동의 지연 보장까지 승인한 결과는 아니다.

## 해석 범위

시험 poll은 대화 50ms·일기 100ms이며 운영 기본 1초와 다르다.
단기 P1의 완료 작업 정리는 매초 수동 호출한다. 별도의 30분 정리 시험만 운영 10초 주기를 검증했다.
실제 공급자의 다양한 입력 품질·RPM/TPM·서비스 전체 비용, 최대 입력 동시 메모리,
30분·25 RPS·지정 만료 작업 유입량을 넘는 지속 처리와 장기 누적·백업 용량은 미검증이다.
250 RPS는 시험 조건의 지속 요청률이며 순간 동시 접속 수나 실제 운영 최대 용량이 아니다.

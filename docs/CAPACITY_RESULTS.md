# 현재 검증 범위

측정 기준일은 2026-10-20이다.
환경은 로컬 Windows / Java 21.0.8 / PostgreSQL 17(4 CPU·4GiB) / 별도 역할 JVM / fake 공급자다.
운영 기본값과 시험 설정은 구분한다. 명령은 [시험 절차](CAPACITY_RUNBOOK.md)에 있다.

## 단기 P1

과거 기록 50,000개·메시지 약 200만 개, 250 RPS, 워밍업 30초·구간당 60초다.
대화 fake 지연은 1초, 일기는 10초다.
API 풀 24, 대화 워커별 슬롯 320·풀 12, 일기 슬롯 48·풀 4를 사용한다.

| 구간 | 예정/접수/완료 | API p95 / p99 | 대화 작업 대기 p95 |
|---|---:|---:|---:|
| 대화 워커 1대 | 15,000 / 15,000 / 15,000 | 25.2 / 56.8ms | 93.9ms |
| 대화 워커 2대 | 15,000 / 15,000 / 15,000 | 39.4 / 205.5ms | 96.3ms |
| 대화 2대 + 지정 일기 1,000건 | 15,000 / 15,000 / 15,000 | 34.0 / 104.9ms | 90.1ms |

세 구간은 시험 지연·처리 목표를 통과한다.
지정 일기 1,000건은 모두 완료됐고 마감부터 완료 p95는 224.6초, 최대 234.7초다.
중복 응답·일기는 0건이며 수동 정리 호출의 삭제 수는 12,868건이다.

## 3분 P1

3분 시험의 결과는 실행마다 변동이 있다.
일부 실행에서 API DB 풀 대기·주입 드롭이 발생하며 전체 반복 통과 상태는 아니다.
첫 메시지를 준비한 사용자 집단으로 실행한 마지막 측정값은 다음과 같다.

| 구간 | 예정/접수/완료 | API p95 | 대화 작업 대기 p95 |
|---|---:|---:|---:|
| 대화 워커 1대 | 45,000 / 45,000 / 45,000 | 26.0ms | 98.0ms |
| 대화 워커 2대 | 45,000 / 45,000 / 45,000 | 25.7ms | 86.7ms |
| 대화 2대 + 일기 생성 | 45,000 / 45,000 / 45,000 | 30.9ms | 92.2ms |

지정 일기 1,000건은 모두 완료됐고 p95는 466.9초다.
이전 구간의 기록도 마감되어 일기 워커 전체 호출은 약 2,141건이다.
혼합 API p95 증가율은 20.24%로 상대 목표 20%를 넘는다.
절대 지연·완료 목표는 충족하지만 3분 P1 전체 합격으로 판정하지 않는다.
지연 변동 원인과 지정 대상 외 마감 부하는 분리되지 않은 상태다.

## 복구와 도구 검증

- 429·timeout·5xx 각 25건은 모두 2회 이내 시도로 완료된다.
- 일기 JVM 종료로 남은 PROCESSING 2건은 운영 5분 리스 후 회수되어 대상 일기 3건이 완료된다.
- 일기 워커가 없는 동안 대화 25건이 접수·완료된다.
- 전달 등록 직전·직후 종료는 각각 작업 1건·일기 1건으로 복구된다.
- 복구 시험의 중복 응답·일기는 0건이다.
- 일기 완료 후 수정 권한·버전 충돌·다음 기록 귀속 검사는 짧은 P0에서 일기 10건과 함께 통과한다.

복구 시험의 429 최소 대기는 2초다.
일기 완료 후 검사 경로의 전체 3분 P1 실행 결과는 아직 없다.

## 해석 범위

시험 poll은 대화 50ms·일기 100ms이며 운영 기본 1초와 다르다.
완료 작업 정리는 매초 수동 호출하므로 운영 10초 주기의 지속 정리량을 보장하지 않는다.
실제 공급자 토큰 한도·해석 품질·RPM/TPM·비용, 최대 입력 동시 메모리,
장시간 유입·삭제 균형과 장기 누적·백업 용량은 미검증이다.
250 RPS는 시험 조건의 지속 요청률이며 순간 동시 접속 수나 실제 운영 최대 용량이 아니다.

로컬 실행 자료는 apps/backend/bootstrap/build/capacity 아래에 생성된다.
대표 실행 식별자는 60초 P1 `2026-10-20T11-24-27.895584200Z-c8710cac`,
3분 P1 `2026-10-20T12-51-00.639744500Z-32f8f9c7`,
복구 `2026-10-20T11-39-24.755627200Z-6555a9b7`이다.
자료는 빌드 산출물이며 저장소 문서의 필수 의존 파일이 아니다.
시험 해석의 개발 사례는 [별도 문서](engineering/capacity-validation.md)에 있다.

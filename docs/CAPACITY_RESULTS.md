## 무료 API 한도와 베타 규모 계산

### 분리 경로의 계획 규모

목표는 하루 실사용자 40명·각 대화 10회, 대화 400회·일기 약 40회다. 운영 승인 수치가 아니다.
Cloudflare Qwen의 짧은 합성 대화 실측은 아래 범위에 한정한다. 실제 사용자 입력 분포·하루 처리량은 운영 관측 대상이다. 합성 10턴의 일기 연결 결과는 아래에 기록한다.
[공식 요금표](https://developers.cloudflare.com/workers-ai/platform/pricing/)의 일일 10,000 Neurons와 입력/출력 100만 토큰당 4,625/30,475 Neurons를 기준으로 계산한다.
출력 150토큰·하루 400회를 가정하면 무료량 30%를 남기는 평균 입력 한도는 요청당 약 2,800토큰이다.
이는 시스템 프롬프트·재전송 문맥을 포함한 입력의 계산값이며 재시도·개발 호출·다른 Workers AI 사용은 추가로 소비한다.
일기 경로의 요청·토큰 한도는 아래 Gemini 절을 따른다.

### Cloudflare Qwen 분리 경로 검증

2026-10-27 실제 대화 응답기·라우터·Cloudflare 공급자와 Gemini 일기 생성기로 확장 검증을 수행했다.
현재 프롬프트는 대화 v3·일기 v4다. 대화 출력 상한은 150토큰, thinking-budget은 0(`/no_think` 소프트 제어)이다.
각 요청은 자동 재시도 없이 한 번 호출하며, 합성 입력만 사용한다. DB·스케줄러는 공급자 시험에서 실행하지 않는다.

| 범위                                   | 호출 수 | 정상 종료·생성 | 지연          |
|----------------------------------------|--------:|---------------:|---------------|
| 대표·부정·계획 변경 각 3회             |       9 |              9 | 514~1,185ms   |
| 무료 최대 원본·최근 문맥 제한 적용 2회 |       2 |              2 | 915~985ms     |
| 범위 이탈·지시 무시 유도               |       2 |              2 | 1,128~1,486ms |
| 실제 AI 응답 누적 10턴                 |      10 |             10 | 463~1,106ms   |
| 누적 대화로 Gemini 일기 생성           |       1 |              1 | 10,395ms      |
| 공급자 동시 호출 8개                   |       8 |              8 | 572~1,277ms   |

**기술 판정:** 32회 모두 정상 종료했다. 대화 31회에 출력 잘림이나 사용자에게 노출된 추론 블록은 관측되지 않았다. 강제 thinking 비활성화를 입증하지는 않는다.
10턴 마지막 응답은 정정된 서울숲과 저녁 동행자 민지를 정확히 반영했다.
실제 Qwen 응답을 포함한 Gemini 일기는 JSON 계약을 충족하고 장소 정정·칭찬 부정·취소된 계획·저녁 동행자·속상함의 부정을 반영했다.
다만 지갑 분실 장소를 도서관으로 연결하는 서술은 원문에서 확정되지 않은 추론이므로 사실 충실도를 무조건 통과로 판정하지 않는다.

**품질 판정:** 정상 생성과 별개로 한계가 확인됐다. 짧은 대화에서 해요체·반말 혼용, 감정 추정, 질문 반복이 남았다.
긴 반복 입력 2회는 이전 ASSISTANT의 일반적인 공감 문구를 그대로 반복했다.
코드 작성 요청에는 일상 주제로 복귀하지 않고 코드 도움을 약속했다. 지시 무시·영어 추론 유도에는 영어 추론은 노출하지 않았지만 사용자의 경험을 1인칭으로 지어내고 문장 수 제한을 넘겼다.
따라서 범위 제한·사실 충실도·말투의 품질 기준을 완전히 충족한 것으로 판정하지 않는다. 앱의 보안 경계나 전문 상담 차단을 이 프롬프트에 의존하지 않는다.

**무료량 계산:** 10턴은 입력 합계 6,380·출력 합계 417토큰으로, 공식 계수 적용 시 약 42.2 Neurons다.
같은 길이의 40명 패턴은 하루 약 1,689 Neurons로 계산된다. 실제 계정 청구량 실측이나 40명 하루 운영 시험이 아니다.
긴 사례는 원본 USER 20개·80,000자와 AI 19개·640자를 최근 20,000자 예산으로 줄여 입력 12,739·출력 32토큰을 사용했다.
긴 사례 요청당 약 59.9 Neurons, 같은 크기 400회는 약 24,000 Neurons여서 무료량을 넘는다. 80,000자 전체 전송 성공으로 해석하지 않는다.

**오류·실행 경계:** Cloudflare 모의 HTTP 401·429·503은 각각 영구 실패·속도 제한·일시 실패로 분류되며 429의 Retry-After 120초가 보존된다. 오류 본문과 인증은 업무 예외에 전달하지 않는다.
플랫폼 68개·대화 51개·일기 21개 단위 테스트와 실제 PostgreSQL 기반 WorkerRoleIsolationIntegrationTest 1개가 통과했다.
역할 통합 시험은 fake 공급자로 워커 분리·순서·종료·리스 회수를 검증하며 실제 공급자 시험과 구분한다.

기술 판정과 대화 품질 판정은 구분한다.
실제 입력 길이 분포·장시간 공급자 가용성·일일 무료량은 베타 운영에서 관측한다.
동시 8회는 개별 클라이언트로 수행한 단기 표본이고 서버·DB 처리량이나 무료 서비스 가용성을 보장하지 않는다.

### Gemini 일기 경로 한도

2026-10-24 Default Gemini Project의 AI Studio 화면에서 gemini-3.1-flash-lite의 한도는 RPM 약 15·입력 TPM 약 250,000·RPD 500이었다.
[공식 한도 안내](https://ai.google.dev/gemini-api/docs/rate-limits)에 따라 API 키가 아닌 프로젝트 단위로 적용하며 배포 시 프로젝트·모델·등급별 표시값을 확인한다.
RPD는 태평양 자정에 초기화하며 사용자의 기록 마감 시각과는 별개다.
하루 40명이 각 일기 1회를 생성하면 기본 요청은 40회다. 재시도·개발 호출·같은 프로젝트의 다른 사용량은 추가로 합산한다.
일기 마감이 겹치면 RPM·TPM을 함께 확인한다. 구독 최대 입력 표본 256,754토큰은 표시된 TPM과 비슷하거나 크므로 단일 호출 성공을 반복 처리량의 보장으로 해석하지 않는다.
Fake AI 서버·DB 시험의 25 RPS는 실제 공급자의 무료 API 처리량과 구분한다.

## Gemini 일기 실제 공급자 검증

2026-10-24 무료 API와 운영 생성기를 사용한 합성 입력 결과다. 일기 프롬프트 v3, 출력 2,000토큰·thinking budget 미지정이며 각 실행은 애플리케이션 재시도 없이 한 번 호출했다. 최대 입력은 사례별 동일 입력 해시와 동일 설정으로 2회씩 실행했다.
현재 일기 프롬프트 v4로는 위 분리 경로 검증의 10턴 연결 1회가 있다.

| 범위                                             | 호출 수 | 결과                                                                                                                             |
|--------------------------------------------------|--------:|----------------------------------------------------------------------------------------------------------------------------------|
| 대표·부정·계획 변경 각 사례의 일기 각 2회        |       6 | 모두 정상 종료·결과 생성                                                                                                         |
| 무료 최대: USER 20개·80,000자, AI 19개·640자     |       2 | 성공 1회: 약 3.3초, 입력 51,248·출력 275토큰. 실패 1회: 약 1.2초 후 HTTP 503 UNAVAILABLE, 공급자 혼잡 분류                       |
| 구독 최대: USER 100개·400,000자, AI 99개·3,360자 |       2 | 성공 1회: 약 3.5초, 입력 256,754·출력 217토큰. 실패 1회: 약 3.2초 후 STOP, 입력 256,754·출력 236토큰, JournalGenerationException |

짧은 사례의 핵심 사건·부정·정정은 반영됐다. 다만 계획 변경 사례에서 사용자에게 근거가 없는 제목의 '데이트', 본문의 '아쉬운 마음'이 관측됐다. 결과 생성 성공과 사실 충실도는 별개의 판정이다.

두 최대 입력의 성공 결과는 서울숲으로의 장소 정정, 발표 완료, 민지와 버섯 파스타·안도감을 반영했고 팀장의 칭찬을 사실로 추가하지 않았다. 구독 최대 결과는 칭찬에 대한 부정을 별도로 서술하지는 않았다.

구독 최대 입력에서 관측한 생성 실패는 검사 단계와 원인이 미확정이며 동일 조건에서 재현되지 않았다. 시험 보고서는 생성기의 고정 실패 메시지를 journalValidationFailure로 보관하며 공급자 오류 본문은 보관하지 않는다. 공급자 정상 종료를 애플리케이션 일기 완성으로 간주하지 않는다.
최대 입력은 반복 문장 중심이다. 현재 설정의 단일 호출 처리 가능성은 확인했으나, 각 사례 2회 결과를 성공률 추정이나 반복 안정성 보장으로 사용하지 않는다. 입력 초과가 확정된 사례는 없으며 요약·분할이나 스키마 변경의 근거는 없다. 재발 시 실패 단계 진단을 기준으로 분석하며, 다양한 비반복 대화·최대 AI 문맥·동시 최대 입력 메모리는 미검증이다.

## 단기 P1

API 풀 24, 대화 워커별 슬롯 320·풀 12, 일기 슬롯 48·풀 4를 사용한다.

## 3분 P1

3분 시험의 결과는 실행마다 변동이 있다.
일부 실행에서 API DB 풀 대기·주입 드롭이 발생하며 전체 반복 통과 상태는 아니다.
첫 메시지를 준비한 사용자 집단으로 실행한 마지막 측정값은 다음과 같다.

| 구간                 |           예정/접수/완료 | API p95 | 대화 작업 대기 p95 |
|----------------------|-------------------------:|--------:|-------------------:|
| 대화 워커 1대        | 45,000 / 45,000 / 45,000 |  26.0ms |             98.0ms |
| 대화 워커 2대        | 45,000 / 45,000 / 45,000 |  25.7ms |             86.7ms |
| 대화 2대 + 일기 생성 | 45,000 / 45,000 / 45,000 |  30.9ms |             92.2ms |

지정 일기 1,000건은 모두 완료됐고 p95는 466.9초다.
지정 대상 외 마감 기록을 포함한 일기 워커 전체 호출은 약 2,141건이다.
혼합 API p95 증가율은 20.24%로 상대 목표 20%를 넘는다.
절대 지연·완료 목표는 충족하지만 3분 P1 전체 합격으로 판정하지 않는다.
지연 변동 원인과 지정 대상 외 마감 부하는 분리되지 않은 상태다.

## 복구와 도구 검증

- 429·timeout·5xx 각 25건은 모두 2회 이내 시도로 완료된다.
- 일기 JVM 종료로 남은 PROCESSING 2건은 운영 5분 리스 후 회수되어 대상 일기 3건이 완료된다.
- 일기 워커가 없는 동안 대화 25건이 접수·완료된다.
- 전달 등록 직전·직후 종료는 각각 작업 1건·일기 1건으로 복구된다.
- 복구 시험의 중복 응답·일기는 0건이다.
- 일기 완료 후 수정 권한·버전 충돌·다음 기록 귀속 검사는 짧은 P0에서 일기 10건과 함께 통과한다.

복구 시험의 429 최소 대기는 2초다.
일기 완료 후 검사 경로의 전체 3분 P1 실행 결과는 아직 없다.

## 해석 범위

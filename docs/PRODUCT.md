# 서비스 기획과 서버 정책

## 목적과 문서 기준

모음은 일기를 직접 쓰기 귀찮은 사람이 인상적인 일을 AI에게 친구처럼 이야기하면,
사용자가 설정한 하루 마감 시각까지의 대화로 일기를 자동 생성·보관하는 서비스다.
사용자는 하루 대화 횟수를 채울 필요가 없다. 접수한 대화가 생성 재료이며 횟수는 사용 상한이다.
일기 생성 완료는 비동기이며 마감 정각의 즉시 완성을 요구하지 않는다.
사용자가 마감 시각을 설정하기 전 기본값은 현지 시각 02:00이다.
선택 가능한 마감 시각의 서버 기본 범위는 현지 18:00부터 다음 날 04:00까지이며 양 끝을 포함한다. 범위는 서버 설정으로 변경할 수 있다.
마감 설정 변경은 다음에 만드는 기록부터 적용한다. 현재 열린 기록은 기존 설정 시각을 유지한다.
마감을 늦춰도 다음 기록은 이전 기록의 다음 표시 날짜에 닫힌다. 예를 들어 02:00에서 04:00으로 바꾸면 02:00에 시작한 다음 기록은 그날 04:00이 아니라 다음 날 04:00에 닫힌다.

이 문서의 확정 사항은 사용자와 합의한 서비스 방향에 근거한다.
구체적인 수치와 경계 규칙 중 합의가 확인되지 않은 부분은 구현 현황과 함께 표시한다.
UI·UX는 설계 중이며 서버 계약으로 화면 형태를 확정하지 않는다.

## AI 모델과 베타 운영 방향

대화 기본 경로는 Cloudflare Workers AI의 Qwen3 30B A3B FP8(@cf/qwen/qwen3-30b-a3b-fp8), 일기는 Gemini 3.1 Flash Lite(gemini-3.1-flash-lite)다. Qwen 분리 경로의 기술 검증과 대화 품질 제약은 검증 현황을 따른다. 프롬프트의 범위 제한·사실 충실도·말투는 완전히 강제되지 않는다.
개발·베타는 Cloudflare Workers AI와 Gemini API 무료 티어로 진행하며 유료 API 전환은 보류한다. 모음의 무료·구독 요금제와 공급자의 API 이용 등급은 별개다.
무료 티어의 호출 제한·일시적인 공급자 오류와 검증한 범위의 품질·지연을 수용한다. 수용 범위와 미검증 범위는 [검증 현황](CAPACITY_RESULTS.md)을 따른다.

프로젝트 화면에서 확인한 Gemini 3.1 Flash Lite의 일일 요청 한도는 500회다.
대표·부정·계획 변경의 짧은 대화·일기와 USER 8만·40만 자의 최대 입력에서 실제 생성 표본을 확보했다. 원문에 없는 일부 감정·관계 표현, 공급자 503과 미재현 생성 실패가 관측됐으며 반복 안정성은 보장하지 않는다. 상세 조건과 한계는 [검증 현황](CAPACITY_RESULTS.md)을 따른다.
계획 규모는 하루 실사용자 40명·사용자당 대화 10회로, 대화 400회와 일기 약 40회다. 재시도·개발 호출은 별도이며 무료량 내 수용 여부는 미검증이다. 사용자별 이용 제한과는 별개다. Cloudflare 실패 시 Gemini로 자동 전환하지 않는다.

사용자가 민감정보와 타인의 식별정보를 입력하지 않도록 서비스 이용약관과 작성 화면에서 안내하는 방향을 확정한다.
약관 문구와 화면의 구체적인 안내 방식은 화면·약관 기획에서 정한다. 현재 서버에 별도 개인정보 분류·차단 기능은 없다.
이 운영 선택은 공급자 약관의 예외나 개별 입력의 적합성을 보장하는 의미가 아니다.

## 합의한 사용자 경험

1. 사용자가 일상 중 기억할 일을 AI에게 이야기한다.
2. 서버가 메시지를 접수하면 AI가 비동기로 답변한다.
3. 사용자가 정한 마감 시각과 마지막으로 접수한 사용자 대화 장소의 타임존으로 기록을 닫는다.
4. 해당 기록의 대화로 일기를 생성하며 완성되면 조회할 수 있다.
5. 마감 후 도착한 새 대화는 다음 기록의 대화가 된다.

발화 시각이 어제여도 새로 접수한 메시지를 과거 일기에 덧붙이지 않는다.
이미 접수한 메시지를 같은 ID로 다시 보내는 것은 재전송이며 처음 저장한 결과를 반환한다.
생성된 일기는 이후 대화 때문에 자동 변경되지 않는다.

저녁 18:00~23:59대에 마감하는 기록은 마감 당일, 00:00~04:00에 마감하는 기록은 마감 전날의 일기로 표시한다.
표시 날짜는 기록을 처음 만들 때 확정하며, 이후 장소가 바뀌어도 바꾸지 않는다.
날짜변경선을 건너 이동하면 서로 다른 기록이 같은 표시 날짜를 가질 수 있다. 이 기록들은 합치지 않고 기록 ID로 구분한다.
화면에서는 같은 날짜의 기록을 구별할 수 있도록 각 기록의 날짜와 마지막 대화 장소 타임존을 함께 보여주는 방향이다. 화면 자체는 아직 구현되지 않았다.
실제 기록 경계는 선택한 마감 시각이다. 02:00 설정이면 03:00에 접수한 대화는 다음 기록에 속한다.
새 장소에서 이전 기록의 마감이 지났다면 이전 기록을 닫고 새 메시지는 새 기록에 저장해 AI 답변 작업을 만든다.
열린 기록의 마감 날짜와 설정 시각은 장소가 바뀌어도 유지한다. 마지막 대화 장소의 타임존으로 그 날짜·시각을 다시 계산한다.
서쪽 이동으로 현지 날짜가 이전 날로 돌아가더라도 그곳에서 가장 가까운 마감으로 앞당기지 않으므로 기록이 길어질 수 있다.
이미 예약된 마감에 도달했거나 새 장소에서 계산한 마감이 지났다면 이 새 기록 귀속 규칙을 적용한다.
기록 길이는 이 마감 경계로 결정한다.
서머타임 전환일에 설정한 현지 마감 시각이 존재하지 않으면 그날의 첫 유효 시각에 마감한다.
같은 현지 시각이 두 번 나타나면 두 번째 시각에 마감한다.

AI는 일상에 공감하는 두세 문장 이내의 짧은 답변과 필요할 때 질문 하나를 제공하는 것을 정책으로 한다.
코드 작성·정치 논쟁·전문 의료·법률 상담 요청에는 답변이 어려움을 정중히 안내하고 일상 주제로 돌아오도록 유도한다.
이 정책은 대화 프롬프트로 적용한다.
AI 답변은 현재 기록의 최근 문맥만 사용한다. 다음 기록이 시작되면 이전 기록의 대화를 AI 답변 문맥으로 넘기지 않는다.
현재 서버의 문맥 상한은 USER·ASSISTANT를 합쳐 최근 100개 메시지·본문 20,000자다. 이 수치는 사용자에게 약속하는 기억량이 아닌 조정 가능한 실행 상한이다.
보관된 전체 대화를 항상 기억하는 동작과는 다르다. 일기 생성은 마감 기록의 입력 전체를 사용한다.
이전 기록을 AI가 참고하는 기능은 현재 범위에 포함하지 않는다.

현재 서버는 사용자 메시지마다 AI 답변 작업을 하나씩 만든다.

## 대화 보관과 조회

대화 데이터는 보관한다. 화면에서 보여줄 기간과 실제 보관 기간은 별개다.
화면은 오늘 중심, 어제까지, 스크롤로 더 오래 보기 등의 방향이 미확정이다.
한 달 정도의 조회 가능성은 논의한 선택지이며 확정 상한이 아니다.
현재 서버는 대화 원본 자동 삭제나 조회 일수 제한을 집행하지 않는다.
보관 기간의 최종값도 미확정이다.

현재 조회 API는 기록 목록과 기록별 메시지 페이지를 제공한다.
생성 결과는 별도 일기로 조회한다. 화면에서 일기와 원본 대화를 연결하는 경험은 미확정이다.

## 대화 한도와 구독

무료 사용자도 대화, 자동 일기 생성·조회, 실패 복구를 이용한다.
구독자는 더 많은 대화와 생성된 일기 제목·본문의 직접 수정을 이용한다.
구독 기능 확대는 핵심 경험을 돕는 편의 기능 중심이다.

사용자에게 안내할 사용 한도는 새 사용자 메시지 횟수다.
메시지 길이는 입력 UI에서 제한할 예정이며 서버도 입력 길이를 검증한다.
현재 서버는 무료 20회·구독 100회, 메시지 최대 4,000자, 사용자별 분당 새 메시지 60회를 집행한다. 이 수치는 서버 설정에서 변경할 수 있다.
새 기록이 시작되면 대화 횟수 한도를 새로 제공한다. 여행으로 기존 기록이 일찍 마감돼도 새 기록에는 전체 한도를 제공한다.

서버는 총한도·현재 기록 사용량·잔여 횟수·열린 기록의 예정 마감 시각을 제공한다. 열린 기록이 없으면 사용량은 0이고 예정 마감 시각은 없다.
새 메시지 한 건을 접수할 때 한 번 차감한다.
중복 재전송과 같은 작업의 실패 복구는 추가 차감하지 않는다.
한도를 소진하면 새 메시지는 거절하고 이미 접수한 대화로 일기를 생성한다.
접수 후 AI 응답이 실패해도 저장 메시지와 최초 차감은 유지된다.
구독 변경 시 현재 기록의 사용량은 유지하고 현재 요금제 한도를 적용한다.

현재 결제·구독 구매·해지 API는 미구현이다.
서버는 저장된 유효 구독 기간과 요금제로 권한을 집행한다.

## 일기 생성과 수정

기록에 대화가 없으면 자동 생성할 기록도 없다.
현재 별도의 최소 대화 수 기준은 없다. 최소 수량 정책은 추후 선택할 수 있다.

일기에는 USER 발화를 경험·감정의 근거로 사용한다.
AI 발화는 짧은 대답·부정·정정을 해석할 문맥이다.
일기의 제목은 한국어로, 본문은 자연스러운 한국어 1인칭 서술로 생성한다. 이 정책은 일기 프롬프트로 적용한다.
생성기는 제목·본문의 공백과 최대 길이를 검사한다.
최대 허용 입력의 실제 모델 처리 가능성과 내용 품질은 별도 검증 대상이다.

생성 결과는 별도 확정 조작 없이 보관된다.
직접 수정은 구독 권한으로 제공하며 동시 수정 충돌을 검출한다.
자동 생성·복구는 사용자가 수정한 현재 결과를 보호한다.
현재 제공 기능은 자동 생성과 직접 수정이며 AI 재작성·문체·길이 선택은 제품 범위 밖이다.

## 실패했을 때의 경험

메시지 접수와 AI 호출은 분리되어 있다. AI 장애가 나도 접수된 대화는 보관된다.
일시적 오류는 제한된 자동 재시도로 복구하고 최종 실패는 작업 상태로 조회한다.
AI 출력이 토큰 상한으로 끊기거나 차단되면 일부 본문을 답변·일기로 저장하지 않고 작업을 실패 처리한다.
이 경우 자동 반복은 중단하며, 수동 복구에는 기존 대화·일기 재시도 정책을 적용한다.
사용자의 실패 재시도는 요금제와 무관하게 제공한다. 대화 응답에는 대기 간격과 총시도 상한을 적용한다.
일기는 자동 처리가 종료된 FAILED 상태에서 작업 생성 후 기본 30일 안에 횟수·대기 제한 없이 수동 재개할 수 있다.
수동 재개 후에도 누적 시도 횟수와 오류 종류에 따른 기존 자동 재시도 판단을 적용한다.

같은 기록의 AI 답변은 사용자 메시지 순서를 따른다.
선행 답변이 최종 실패하면 후속 답변이 진행할 수 있다.
이미 후속 답변이 실행 중이거나 완료됐으면 과거 실패 답변의 재삽입을 거절한다.
상세 수치와 API 결과는 [대화 계약](CONVERSATION.md), [일기 계약](JOURNAL.md)을 따른다.

## 확정된 접수·작업 보존 정책

클라이언트 발화 시각은 서버 접수 시각보다 최대 5분 뒤까지 허용한다. 초과한 요청은 저장하지 않고 거절한다.
완료된 대화 응답·일기 생성 작업 행은 완료 후 30일이 지나면 정리한다.
실패한 대화 작업 행은 최근 실패 후 30일까지 보관하며 재시도는 대화 정책을 따른다.
실패한 일기 작업 행은 작업 생성 후 30일까지 보관하고 재시도를 허용한다. 재실패해도 기한은 연장하지 않는다.
작업 행의 보존 기간은 원본 메시지와 생성된 일기의 보존 기간과 별개다.
실패 작업의 30일 정리는 서버가 집행한다. 정리 배치 전이라도 기간이 지나면 재시도를 거절한다.

타임존은 클라이언트가 IANA 식별자로 보낸다. 위치 좌표를 수집하는 API는 없다.

## 개발 범위

현재 인증은 Google ID 토큰 검증 후 내부 사용자와 기기별 세션을 발급하는 방식이다.
같은 기기에서 다시 로그인하면 해당 기기의 기존 세션을 교체한다.
access token 기본 수명은 15분, refresh token은 로그인·갱신 시점부터 30일이다.
refresh는 토큰을 회전시키며 직전 토큰의 30초 내 중복 갱신은 충돌로 처리하고 세션을 유지한다.
refresh token은 세션 ID와 무작위 비밀값을 HMAC-SHA256으로 보호한다. 진위 검증에 실패한 토큰은 세션을 변경하지 않고 거부한다.
현재 토큰은 갱신하고, 직전 토큰의 30초 유예 조건 밖에서 서버가 발급한 과거 토큰이 재사용되면 해당 세션을 폐기한다.
로그아웃은 현재 토큰 또는 유예 시간 내 직전 토큰이 확인된 경우 refresh 세션을 폐기한다. 그 밖의 입력도 성공 응답을 반환하지만 세션은 변경하지 않는다.
이미 발급된 access token은 세션 폐기 후에도 만료까지 유효하다.

API 서버의 refresh token 전용 키는 `moeum.auth.session.signing-secret`(`MOEUM_AUTH_SESSION_SIGNINGSECRET`)으로 주입한다.
운영에서는 무작위로 생성한 최소 32바이트의 비밀키를 사용하며 access token 서명 키와 분리한다. 모든 API 인스턴스와 재시작 전후에 동일한 키를 유지해야 한다.
키를 교체하면 기존 refresh token은 모두 진위 검증에 실패하므로 재로그인이 필요하다. 이전 키를 함께 허용하는 키 순환은 지원하지 않는다.
이 수치는 현재 인증 설정이며 사용자 대상 로그인 UX는 미확정이다.

현재 서버에는 Google 로그인과 기기별 인증 세션, 기록·설정·한도 조회,
대화 접수·응답·실패 복구, 자동 일기·구독 수정, 역할별 작업 실행이 있다.
클라이언트 화면, 푸시 알림, 실제 결제, 계정 탈퇴와 원본 삭제 흐름은 미구현이다.
운영 용량의 확인 범위는 [검증 현황](CAPACITY_RESULTS.md)을 따른다.

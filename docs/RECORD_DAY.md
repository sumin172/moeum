# 하루 기록과 자동 일기 정책

사용자가 정한 하루의 마지막 시각과 마지막으로 **접수한 사용자 대화의 장소 타임존**으로 기록을 마감한다. 대화 기록은 보관하지만, 일기 생성은 마감된 RecordDay 하나에 속한 메시지만 사용한다.
사용자 설정 전 마감 기본값은 해당 타임존의 02:00이다.
설정 가능한 시간의 서버 기본 범위는 18:00부터 다음 날 04:00까지이며 양 끝을 포함한다. `moeum.conversation.record-day` 설정으로 범위를 바꿀 수 있다. 범위 밖 설정 요청은 400이다.

## 귀속과 마감

- 새 USER 메시지는 서버가 사용자 상태 잠금을 잡고 접수한 시각에 열린 RecordDay에 저장한다. `occurredAt`은 표시용 발화 시각이며 과거 기록을 찾거나 다시 여는 기준이 아니다.
- `clientMessageId`가 같은 재전송은 마감 전후와 관계없이 처음 저장한 메시지와 작업을 반환한다. 새 ID로 접수한 메시지는 이전 발화 시각을 담았어도 현재 기록에 속한다.
- 열린 기록의 `closeAt`에 도달했으면 배치가 아직 실행되지 않았어도 잠금 아래 먼저 닫는다. 마감 정각부터 다음 RecordDay다. 오래 접속하지 않은 사용자는 다음 접수 시 현재 기록 하나만 만들며 빈 날의 기록·일기는 만들지 않는다.
- 최초 메시지의 타임존과 사용자 설정 마감 시각으로 다음 `closeAt`을 정한다. 열린 기록에 새 USER 메시지를 넣기 전에 기록의 기존 `closeDate`·`closeTime`을 마지막 대화 장소의 새 타임존으로 계산한다. 새 장소에서 가장 가까운 마감 날짜로 `closeDate`를 바꾸지 않는다. AI 응답이나 조회는 장소·마감을 변경하지 않는다.
- 마감 시각 설정 변경은 이미 열린 기록에 적용하지 않는다. RecordDay는 생성 당시의 `closeDate`·`closeTime`을 유지한다.
- 다음 기록의 마감 시각이 이전 기록과 다르면 이전 표시 날짜의 다음 날부터 새 기록을 만든다. 02:00에서 04:00으로 늦춘 경우 같은 새벽 04:00에 다시 닫지 않고 다음 날 04:00에 닫는다. 기존 `displayDate`·`closedAt`을 사용하며 별도 상태를 저장하지 않는다.
- 장소 이동으로 계산한 마감이 이미 지났다면 기존 기록은 현재 접수 시각에 닫는다. 이전 기록의 원본 순번·마지막 대화 장소는 유지하고 새 메시지는 새 기록에 저장해 답변 작업을 만든다. 이미 저장된 대화를 소급해 제외하지 않으며 새 기록의 시작 경계는 이전 기록 마감 이후다.
- 새 장소에서도 마감 전이면 열린 기록의 타임존·예약만 갱신한다. 이미 기존 예약 마감에 도달한 기록은 장소 이동으로 연장하지 않는다.
- 서머타임 전환으로 설정한 현지 마감 시각이 존재하지 않으면 첫 유효 시각에 마감한다. 같은 현지 시각이 두 번 나타나면 두 번째 시각에 마감한다. 날짜변경선 이동으로 표시 날짜가 같아도 별개의 기록일 수 있으므로 `displayDate`에 사용자별 유일 제약을 두지 않는다.
- 새 기록의 시작점은 현지 이전 마감과 사용자 직전 기록의 확정 마감 중 늦은 시각이다. 마감을 늦춰 다음 표시 날짜로 넘긴 경우에는 직전 기록의 확정 마감부터 시작한다. 시간대 이동으로 기록 구간이 겹치지 않게 한다.

`closeAt`은 현재 예약된 절대 마감 시각이다. `closedAt`은 확정된 논리적 마감 경계이며 배치가 늦게 실행된 시각과 다르다. `sourceRevision`은 해당 기록의 USER 메시지가 추가될 때 증가하는 순번이며 대화 응답 순서에도 사용한다. `streamSequence`는 USER·ASSISTANT가 실제로 기록에 저장된 순서다.

## 생성 입력과 재시도

닫힌 RecordDay에는 USER 메시지를 추가하지 않는다. 생성 작업의 최초 실행·재시도는 같은 기록의 메시지를 다시 읽는다. 재시도 입력의 경계는 마감된 기록과 마지막 USER의 기존 순번으로 결정한다.

일기 입력은 마지막 USER 메시지까지의 USER·ASSISTANT 스트림을 읽는다. USER는 일기에 쓸 사실의 근거이고 ASSISTANT는 짧은 답변을 해석할 문맥이다. 마지막 USER 뒤에 늦게 저장된 AI 응답과 마감 이후에 완료된 AI 응답은 제외한다. 본문 조회는 사용자 상태 잠금을 유지하지 않는다. AI 호출 역시 DB 트랜잭션 밖에서 수행한다.

마감과 대화 접수는 사용자 상태 → RecordDay 순서로 잠근다. 메시지 접수·원본 순번 증가·응답 작업 등록은 한 트랜잭션으로 처리한다. 마감 뒤 Journal 생성 작업 등록은 별도 전달 워커가 담당하며 전달 리스와 확인 상태로 재기동·중복 실행을 복구한다. 생성 작업 자체의 리스·멱등성과 사용자 수정본 보호도 유지한다.

사용자 상태 행에는 설정 마감 시각만 둔다. 열린 기록은 `record_days`의 사용자별 열린 기록 유일 인덱스로 찾아 잠근다.

## 표시와 조회

RecordDay의 UUID가 일기·대화 조회의 식별자다. 표시 날짜는 첫 기록 생성 시 정해지며 타임존 이동 후에도 바뀌지 않는다. 18:00~23:59대 마감은 현지 마감 당일, 00:00~04:00 마감은 현지 마감 전날을 표시한다.
서로 다른 기록이 같은 표시 날짜를 가질 수 있으며 합치지 않는다. 기록마다 저장된 마지막 대화 장소 타임존을 날짜와 함께 보여주면 화면에서 구별할 수 있다. 현재 화면은 구현되지 않았다.

대화 보관 기간과 화면에서 보여주는 기간은 별개의 정책이다. 조회 기간을 바꾸더라도 이미 저장한 메시지의 RecordDay 귀속을 재계산하지 않는다.

## 핵심 검증

- 마감 정각 또는 배치 지연 중 접수한 새 메시지는 다음 기록에 저장된다. 오래된 `occurredAt`도 이 결과를 바꾸지 않는다.
- 이미 접수한 메시지의 재전송은 원래 기록과 메시지를 반환하고 quota·응답 작업을 중복 생성하지 않는다.
- 닫힌 기록의 생성 입력은 새 기록의 접수와 늦은 AI 완료, 일기 재시도 이후에도 같은 USER·ASSISTANT 문맥이다.
- 여행·DST에서도 기록 경계가 겹치지 않고 새 대화 장소의 마감 여부에 맞춰 귀속한다.
- 마감 설정 변경은 현재 기록의 마감 시각을 유지하고 다음 기록부터 적용한다. 서버는 설정 시간 범위를 검증한다.
- 전달 등록 실패·리스 만료·프로세스 재시작 뒤에도 일기 생성 작업은 기록당 하나이고 사용자의 수정본을 덮어쓰지 않는다.
